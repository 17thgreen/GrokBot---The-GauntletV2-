## RULE_BEFORE (full text or precise pointer)

- Informal chat door policy; no AMD on skill/MCP admission
- `AUTHORITY.md` / `INSTITUTIONAL_LOCK` — no order tools as culture, not as install-path law

## RULE_AFTER (operable replacement)

**Classification:** TOOL / SKILL ADMISSION LAW (`RETROACTIVE: NO`).

1. A skill or MCP may **implement existing doctrine** (Clock join, Examiner metrics, Archivist templates, allowlisted read adapters). It may **not** add doctrine, expand domain, or invent a new hard authority.
2. **Order-shaped tools BAN even if disabled.** Staging, sizing, placement, or trade-loop shapes are prohibited on the shared computer regardless of “disabled,” “dry-run,” or “paper” labels in the tool description.
3. **Before pin:** scan the artifact; write / update `SOURCE.md`; record license. No pin without those.
4. **Team marketplace is the only install path.** No ad-hoc curl-to-disk installs of skills/MCPs onto the shared computer outside that path.
5. **Capability permissions ≠ `SKILL.md` metadata.** The capability / permission line is binding. Do not soften it because the SKILL.md prose claims read-only, educational, or “disabled orders.”
6. Enablement of a read-only MCP is Treasurer + Clock allowlist under this AMD — **not** Intake Auditor READY (see AMD-004 / Intake charter).
